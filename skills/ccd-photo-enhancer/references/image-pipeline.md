# L2 本地像素管线：安全边界与格式策略

`L2` 表示本地 Pillow/NumPy 对像素做确定性处理。它不是生成模型，不理解“脸”“天空”“物体”语义；处理不会创造、删除、移动或重构物体，且不做裁切/缩放。照片原有的物理照明也不会被真实重建。此路径不联网、不上传图片。

## 能力与输入

执行 `scripts/apply_ccd.py` 前确认本地 Python 可用且能导入 Pillow 与 NumPy。脚本不安装包、不下载模型、不调用在线 API。支持的输入容器以 Pillow 能稳定解码的静态 JPEG、PNG、WebP 为主；拒绝多帧动画和解码失败输入。HEIC/HEIF 当前不能解码（无 pillow-heif）：单张会明确报错，批处理默认计入失败，加 `--skip-unsupported` 后记为跳过；请提示用户先在本机导出 JPEG/PNG，不要静默转交外部服务。脚本默认上限为 60 megapixels，覆盖常见 48MP 手机照片；可用 `--max-pixels` 向下调低以限制内存，但不能突破 60MP 安全上限。超过上限时明确拒绝且不自动缩放，避免与“保持原尺寸”的约束冲突；需用户选择其他本地处理方案。

## 方向、比例与尺寸

读取 EXIF Orientation 并先应用 `ImageOps.exif_transpose`，再记录显示方向和尺寸。输出像素尺寸与方向校正后的输入严格相同；不裁切、不拉伸、不缩放，也不修补背景。宽高比因此保持显示比例。处理后重新打开输出并校验尺寸和可解码性。

## 色彩空间与像素格式

- 若输入含可解码 ICC profile，使用 Pillow `ImageCms` 转至 sRGB，再处理并将 sRGB profile 写入输出；不能解码/转换时明确失败，不能静默按 sRGB 猜。
- 无 ICC 的 CMYK JPEG 使用 Pillow 转 RGB 并在报告中标注“输入无 ICC，使用 Pillow 默认转换”；不把该转换称作精确颜色还原。
- 8-bit RGB/灰度和带 alpha 的 PNG 可处理。保留 alpha 数值，颜色效果只施加在颜色通道；默认透明输入输出 PNG。显式要求 JPEG 但输入含透明像素时拒绝，除非未来实现了用户明确指定的底色合成流程。
- Pillow 解码的 16-bit 整数灰度图可通过固定 0–65535 范围量化至 8-bit 并在结果中注明位深转换；不支持浮点像素模式或无法判定量程时拒绝，不用图像自身 min/max 归一化以免每张图被任意重映射。
- CMYK、索引色、灰度等模式应转为明确的 RGB/sRGB 处理路径。若处理实现不能保持其 ICC 语义，则应安全失败或给出清晰警告。

## 输出与隐私

- 输出与源文件同目录，格式自动选择：带透明通道或 PNG 输入默认输出 PNG；不透明 JPEG/WebP 输入默认输出 JPEG。可用 `--out` 指定绝对/相对目标路径和格式；允许 `.jpg/.jpeg/.png/.webp`。
- 默认名：`<stem>_ccd-<preset>-<strength>.<ext>`。目标已存在时自动选择 `-2`、`-3` 等不冲突名字。绝不原地覆盖；输入/输出解析为同一文件时直接拒绝。若保存过程中失败，清理仅由本次进程创建的不完整输出。
- JPEG `--quality` 默认 94，允许 70–100；为避免 bundled libjpeg 在高熵内容的 optimized Huffman 编码中报 `Suspension not allowed here`，JPEG 显式使用 `optimize=False`。JPEG 采用 `subsampling=0`（4:4:4，保留色彩边缘但文件通常更大）；在 48MP 合成 smoke 样例上的输出体积/耗时不能代表其他照片。PNG 保留 alpha；WebP 只在用户明确指定时输出。输出不保留源 EXIF、GPS、序列号或拍摄时间；嵌入经转换/确认的 sRGB ICC 不属于个人 EXIF。不要保留 GPS 作为“复古效果”。
- 主强度 0 关闭风格效果，但仍可能转 sRGB、校正 EXIF Orientation、量化 16-bit 灰度及重新编码。PNG 且无需色彩转换时像素可保持不变；JPEG 重编码可能有损，不能称作无损 no-op。
- 默认 seed 为 0。颗粒由 NumPy `default_rng(seed)` 生成；同一尺寸输入、参数、seed 和 Pillow/NumPy 版本可复现。锐化半径按长边 `max(0.5, long_edge / 3000)` 归一；颗粒是逐像素噪声，像素颗粒在缩放/不同分辨率下的视觉尺寸仍会变化，不保证不同分辨率看起来完全一致。跨版本可能造成字节差异，因此报告包含依赖版本和实际参数。
- 处理前检查像素总数，默认最多 60MP；`--max-pixels` 可设为 1–60MP 以控制内存，若当前值低于安全上限，可提高到 60MP。采用分块处理和分块剪切指标以限制临时数组内存。超过 60MP 时拒绝、不自动缩放；不要自动上传或缩小用户原图。

## 文件夹批处理

- 命令形式：`apply_ccd.py <输入目录> --batch --out <另一个已存在目录> --preset <预设> --strength <强度> --seed <seed> [--skip-unsupported]`。批处理必须显式提供 `--out`，且输出目录不得与输入目录相同；不自动创建目录，不递归子目录。
- 只枚举输入目录第一层的 JPEG、PNG、WebP、HEIC、HEIF 文件；HEIC/HEIF 默认逐张记为失败（`not_processed`，错误写明当前环境不支持该格式），加 `--skip-unsupported` 后改为 `skipped` 并写 `reason`。`reason` 固定以「已跳过：」开头并包含「未生成输出文件」，不得改写成成功；跳过不计入失败，也不生成输出。其他普通文件计入 `ignored_non_photo_files`；目录里没有任何候选照片时不抛错，而是返回 `nothing_processed` 与「目录中没有可处理照片。」。排序按文件名进行，报告保留每个输入的绝对路径。
- 每张图沿用单张管线的格式、方向、ICC、alpha、像素上限和输出校验规则。默认文件名仍为 `<stem>_ccd-<preset>-<strength>.<ext>`，冲突时添加序号；重复运行不会覆盖先前输出。
- 所有输入使用同一个显式 seed 和参数，报告中的 `seed_policy` 为 `same-explicit-seed-for-each-source-image`。同尺寸图片因此可能共享颗粒随机场，这不等于跨分辨率视觉一致。
- 批量 `--preview` 当前明确拒绝；先对单张代表照片使用预览。批处理输出一个汇总 JSON，`status` 为 `processed`、`processed_with_skips`、`partially_processed` 或 `nothing_processed`，并在 `results` 中保留逐张完整报告、跳过原因或错误。
- CLI 退出码：`processed` 与 `processed_with_skips` 为 0；`partially_processed` 为 1，同时向 stderr 写部分失败摘要、向 stdout 写完整汇总；`nothing_processed` 为 2，完整汇总写 stderr。跳过不计入失败，但也不等于成功——报告必须保留 `skipped_files` 与 `notice`（`已跳过 N 个文件：当前环境不支持这些格式；未生成对应输出文件。`），单张跳过则以「已跳过：」开头提示并退出 2。`nothing_processed` 必须按场景区分措辞：空目录 →「目录中没有可处理照片。」；全部跳过 →「未生成输出：N 个文件均因格式不受支持而被跳过。」；全部失败 →「未生成输出：N 个文件均处理失败；…」；混合 → 同时给出跳过与失败数量。「跳过」不是「失败」，但没有输出就不能报告成功。部分结果会保留，已成功的输出不回滚，但不能把部分成功或含跳过的批次描述成整组完成。

## 指标与解释

脚本 JSON 报告中提供：输入/输出绝对路径、输入/输出格式、预设与三轴、强度、seed、依赖版本、方向校正后的尺寸、alpha 是否保留、EXIF 是否剥离、ICC/sRGB 状态、近白/剪切通道/近黑比例（处理前后）、锐化半径和 JPEG 参数。这些指标只能提示剪切/格式问题，不证明美学质量或人物身份。没有分割掩膜时不计算“肤色变化”，也不声称检查了人脸；人像需人工观察偏橙/偏色，必要时降低色彩子效果。

高光可按配方叠加暖色辉光；直闪高光还会向白抬升，抬升量随亮度趋近 1 而收敛，因此不会出现纯白平台；只有输入中 ≥254 的高光点被钉成纯白。辉光在四分之一分辨率生成模糊掩膜，再以一张共享的 8-bit 整图掩膜采样，避免全图 float32 RGB/亮度/掩膜中间数组和分块插值接缝。直闪预设另有闪光衰减（中心提升暗部/中间调、边缘更暗）和黑位压深；中心提亮使用有界曲线，不新增通道剪切。暗角使用近黑保护与受限的夜景加强，像素乘法上限 45%。L2 仍不生成真实机顶闪光投影阴影、镜头眩光、人物蒙版、日期戳或 JPEG 相机原生伪影；这些要么需要场景/对象感知，要么需要另一个明确步骤，不能把算法近似说成物理相机仿真。

## 失败回退

- 输入打不开、HEIC、超限、损坏、ICC 无法转换或输出无法写入：单张处理返回非零状态，错误写入 stderr，不能留下“已处理”的结论；单张 HEIC 加 `--skip-unsupported` 时报告 `status=skipped`、`image_written=false`，提示以「已跳过：」开头并包含「未生成输出文件」，仍返回 2 因为没有任何输出。批处理逐张记录失败或跳过，按四种状态返回 0/0/1/2；已成功文件保留，失败与跳过的文件都不生成输出。
- 本地处理失败时可选择 L3 给提示词；只有用户授权且存在合适 L1 后端时才调用生成式服务。L2 未成功不得静默转 L1 上传。
- 用户请求修复划痕、扩图、去除物体、改造光线/背景、准确复原某款机型、保护身份保证等超出像素滤镜能力的任务时，向用户说明边界并选择 L1/L3。
